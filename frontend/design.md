You are an expert React.js developer and senior UI/UX designer. Build a complete, production-ready React component (`App.jsx`) using Tailwind CSS, Lucide React icons, and React Toastify (or react-hot-toast) for notifications. The application must bridge a dynamic, language-aware UI to a FastAPI backend streaming a native file response.

### 1. Objective
Create a modern, clean, single-page application form that collects 7 text/selection fields and 1 logo image file (total 8 fields). The frontend must strictly validate all fields before sending a `multipart/form-data` request to a backend API. Upon receiving a successful `FileResponse` from the backend, it must natively download the binary `.docx` file directly to the user's local machine, whether running on localhost or hosted live.

### 2. Form Workflow & Strict Validation Rules
- **Initial State:** The user must first see a mandatory language selection step (Dropdown or Radio group) with options: **English** or **Urdu**.
- **Conditional Field Opening:** The rest of the form fields must remain locked/hidden and only open after a language is selected.
- **Language-Specific Input Restriction:** 
  - If the user selects **Urdu**, the question input fields must strictly accept only Urdu characters. Use regex validation on submit (`/^[\u0600-\u06FF\s0-9?؟]+$/`) to block English characters in the question fields, and apply `dir="rtl"` to the question input boxes for natural typing.
  - If the user selects **English**, the question input fields must strictly accept English text. Use regex validation (`/^[A-Za-z0-9\s.,?!'"()-]+$/`) to block Urdu/non-English text.
- **Dynamic Array for Questions:** 
  - Implement a dynamic list where the user can click an **"Add Question"** button to append a new text input field. 
  - Each question must be its own input string inside an increasing array. Include a "Delete" button next to appended questions (ensuring at least 1 question remains).
- **Empty Field Validation:** On form submission, write strict client-side validation logic. If *any* field (including the logo file or any empty question row in the dynamic list) is left empty or fails regex constraints, halt submission and trigger an error toast showing exactly which field is missing or invalid.

### 3. Form Field Specifications (Total 8 Fields)
1. **Language** (`language`): Primary Select Dropdown (Urdu or English) - Unlocks the form.
2. **Assignment Number** (`assignment_no`): Number Input (e.g., 1, 2)
3. **Course Code** (`course_code`): Text Input (e.g., 8611)
4. **Semester** (`semester`): Select Dropdown or Text Input (e.g., Spring 2026, Autumn 2026)
5. **Student Name** (`student_name`): Text Input (e.g., FARHAT NAZ)
6. **Registration ID** (`registration_id`): Text Input (e.g., 0000844005)
7. **Questions** (`questions`): Dynamic array of strings generated by the "Add Question" button.
8. **University Logo** (`logo_image`): A Drag-and-Drop / Click upload zone supporting image types (.png, .jpg, .jpeg) with a clear image thumbnail preview and size restriction check (< 200KB) on selection.

### 4. API Integration & Binary File Download Logic
When the validated form is submitted, trigger this exact flow:
- **Endpoint:** `http://127.0.0.1:8000/api/chat`
- **Method:** `POST`
- **Payload Architecture (Strict Matching):**
  - Instatiate `const formData = new FormData();`
  - Append the file binary: `formData.append('logo_image', selectedFile);`
  - Construct the text payload exactly matching the expected backend structure, wrap it in a stringified payload, and append it:
    ```javascript
    const payload = {
      assignment_no: Number(assignmentNo),
      course_code: Number(courseCode),
      semester,
      student_name: studentName,
      registration_id: registrationId,
      questions: questionsArray,
      language
    };
    formData.append('chatData', JSON.stringify(payload));
    ```
- **Loading State:** Disable all controls and show a spinning loader on the button saying *"Generating Document..."*
- **Toast Notifications:** Fire an instant loading toast when the network request fires. If successful, fire a success toast: *"Assignment generated! Downloading your Word file..."*

- **Dual-Type Response Parsing (Critical Block):**
  Since the backend can return either a binary file stream (`200 OK` FileResponse) OR a JSON validation error response (`400/422/500` JSONResponse), your `fetch`/`axios` call must fetch the response as a raw `blob()`. 
  - **Check `response.ok`**: If the response is NOT okay, you must convert the blob back into text using a `FileReader` or `await blob.text()`, parse it via `JSON.parse()`, and extract the exact error string (e.g., `data.detail.error`) to show in an error toast.
  - **If `response.ok` is true**: Process the blob via the **Native File Downloader**:
    ```javascript
    const blob = await response.blob();
    const downloadUrl = window.URL.createObjectURL(blob);
    const tempLink = document.createElement('a');
    tempLink.href = downloadUrl;
    tempLink.setAttribute('download', `${studentName}_Assignment.docx`);
    document.body.appendChild(tempLink);
    tempLink.click();
    document.body.removeChild(tempLink);
    window.URL.revokeObjectURL(downloadUrl);
    ```
